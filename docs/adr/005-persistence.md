# 005 - 消息持久化

- Status: accepted
- Date: 2026-09-22
- Context: 第二轮 grilling，用户主动要求把第一轮砍掉的持久化带上。第一轮决策是"内存存储，重启丢失"（ADR 001），本 ADR 部分取代它：消息持久，网段其余不变。
- Decision:
  - 只持久化 `chat` 消息；`join`/`leave` 是瞬时在场信息，仍纯内存广播，不存不回放。
  - 存储：每房一个 JSON 文件，`data/<房名>.json`；零依赖，出问题可直接打开文件看。
  - 上限语义不变：每房最近 100 条（内存裁剪逻辑复用，落盘即裁剪后结果）。
  - 重启后：房间由文件重建（空房无文件即不存在——注意这与 ADR 004"空房保留"配合：运行时空房保留在内存，重启后无消息的房自然消失）。
- Consequences: 需要 `data/` 目录与写盘时机（收到 chat 即追加/重写）；房名需做文件名安全处理；`npm run dev` 仍一键启动。
